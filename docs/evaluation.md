# Evaluation protocol

The committed `results/manifest.json` is the publication source. The report renderer validates populations, measured intervals, and split discipline before rendering complete documents. Its check mode compares whole files and rejects unexplained publication edits.

Each extractor is measured on gold words and Tesseract words. Gold annotations isolate extraction behavior; OCR observations include recognition errors. The same normalized field definitions and document-level sample units are used in both columns. Results identify generated documents separately from the full original CORD splits. The project maps CORD to selected fields and line items; these are project metrics, not a reproduction of the official CORD benchmark metric.

Training fits the learned token model. Validation fits calibration and selects a routing threshold using the stated costs. Test observations report the selected policy. Test data must not select the threshold, and a deliberate test-selection mutation is rejected by the publication gate.

Calibration is fitted separately for generated documents and public CORD receipts, within each backend and field type. Generated calibration includes the original validation pages and nonbaseline controlled variants of those same parents. The reported reliability curves use separate test parents and their variants. Variant counts and independent parent counts are both shown. Reliability intervals resample whole parent documents; for an all-correct or all-incorrect bin, a Wilson bound based on the independent parent count avoids a zero-width claim of certainty. Receipt header fields without reference labels have no calibration population and cannot inherit a generated-page confidence claim. The operating point remains selected on original validation documents and reported on original test documents; the stress-test mixture is not substituted for the inbox population.

Intervals quantify sampling uncertainty on the recorded population. They do not cover changes in vendors, language, imaging equipment, template design, or financial loss assumptions. A small number of automatically approved pages cannot establish a production error rate. An empty automatically approved group has no observable conditional error rate and must be reported as unavailable.

The degradation sweep uses every generated test parent with known truth at five preselected levels of blur, skew, compression, resolution, noise, and photographed-page transforms. Parameter units and severity order are recorded in the generated configuration. Each point has a different image of each independent parent, and its interval resamples those parents. Pooling variants does not create additional independent documents. The lab displays all six curves together and the first measured level below each backend's field-F1 floor. A single-document illustration in the browser is not a population estimate.

Reviewer corrections can become training examples only for the optional API's explicit retraining path. Browser practice is excluded from the canonical benchmark. A training improvement is not guaranteed, and the before/after report must preserve a decline when one occurs.

Rule labels include direct consequences of each injected defect: changing an invoice total creates both an arithmetic failure and a mismatch with the independently recorded purchase-order total. These propagated consequences are expected positives, not false alarms. Receipt header fields absent from CORD labels receive no generated-header calibration claim; they require review.

The generated test set includes positive examples for all six business rules, including a supported ISO currency that conflicts with the independent vendor master. Precision measures correct flags among flags; recall measures detected injected defects among injected defects. TP, FP, FN and TN are reported alongside Wilson intervals. This end-to-end scorecard includes OCR-induced false alarms and is distinct from isolated unit tests of a rule supplied with perfect fields.

Demonstration documents only. Generated invoices contain fictional vendors and transactions. Public CORD receipts are attributed separately.
