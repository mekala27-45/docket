# Serving docket

These are demonstration documents: a public receipt dataset and generated invoices. The published site is a recorded demonstration on GitHub Pages. The API is an optional local service; its presence in this repository does not establish a live cloud deployment.

Set `DOCKET_WRITE_TOKEN` to a private, randomly generated value, then start `uv run uvicorn packages.api.main:app --host 127.0.0.1 --port 8080`. The default database is `docket.sqlite3`. `DATABASE_URL` can select PostgreSQL with a `postgresql+psycopg://` connection string. Tables are created at startup. A compatibility migration adds immutable correction snapshots and provenance to older databases; existing rows receive empty metadata and are excluded from retraining until reviewed again.

`GET /health` checks a fresh database query. `GET /v1/queue` returns documents by descending risk, then creation time. `GET /v1/documents/{id}` returns extraction and rules; `GET /v1/trace/{id}` includes the trace and audit events. Uploaded redacted pixels are served at `GET /v1/documents/{id}/image`. Public seed images remain on the static site.

Write endpoints require `Authorization: Bearer YOUR_TOKEN`. With no configured token, writes are disabled. `POST /v1/documents` accepts multipart `file` with PNG, JPEG, WebP, or one PDF page, at most 10 MiB and 25 million decoded pixels. `POST /v1/extract` takes `document_id` and `backend` (`rules` or `tokens`). `POST /v1/review/{id}` takes corrected `fields`, optional `line_items`, `decision` (`accept` or `reject`), and optional `reason`.

A review transaction locks the document on PostgreSQL, updates its extraction, inserts the correction, inserts an audit event, and commits. The success response is constructed only after commit. A commit failure cannot be acknowledged as a saved correction. The SQLite implementation is for one local API process, with database locking and a busy timeout. A human accept decision is recorded separately from machine auto approval; a human acceptance does not imply that business rules passed.

`POST /v1/retrain` uses each document's latest review only when that review is accepted. It rejects an empty correction set. Rejections supersede earlier acceptances. Only explicitly supplied fields and rows are training evidence; inherited model predictions are not relabeled as reviewed truth. Unambiguous matching OCR spans are used, while unreviewed, redacted, ambiguous, and unalignable spans are masked. The pipeline evaluates both models on identical frozen test labels and both gold and Tesseract OCR, with source-specific CORD results and confidence intervals. `POST /v1/retention` runs the expiry job. Refer to the privacy policy before training on any upload.

`CORS_ORIGINS` is an explicit comma-separated origin allowlist. Do not publish the write token in a Pages environment variable, source file, screenshot, or client bundle. Users supply it only when connecting to their own API. This token gate is deliberately minimal authentication for a demonstration.

For local PostgreSQL, set the token in your shell and run `docker compose up --build`. The database credentials in `compose.yml` are local demonstration credentials and the PostgreSQL port is not exposed to the host. Production operators must configure private credentials separately. `fly.toml` is a deployment template requiring a unique app name and separately configured database and write-token secrets.

Run `uv run python scripts/check_persistence.py` for the process-boundary check. It launches Uvicorn on loopback, uploads an in-memory generated invoice, posts a correction, then starts a separate interpreter and engine to read the document, correction, and audit. All temporary state is discarded after the check.

## Correction provenance and export

`POST /v1/review/{id}` also accepts `review_source`: `human`, `simulation`, `integration_test`, or `unspecified`. The default is `unspecified`. The API stores an immutable OCR snapshot with the reviewed values and audit ID in the same transaction. A client declaring `human` is counted as a client-declared human review, not as independently verified reviewer identity. Automated fixtures declare `integration_test`; generated validation-truth examples remain `simulated_ground_truth`. Existing unspecified data is never automatically reclassified as human.

`GET /v1/corrections/export` requires the write token and returns a versioned JSON export with the latest accepted snapshots, source counts, excluded legacy/rejected counts, and a SHA-256 digest. The export contains only redacted stored text, but remains private local data. Keep it under ignored `artifacts/`, never in the public site bundle.

For an actual local review collection, run `uv run python scripts/retrain_from_corrections.py --api-url http://127.0.0.1:8080 --provenance client_declared_human`. The command reads the token from `DOCKET_WRITE_TOKEN`, exports the exact selected records, and asks the API to retrain. The API rejects a changed export digest instead of silently training on a newer review set. An offline run can use `--corrections artifacts/my-export.json` instead of `--api-url`. Provenance selection is mandatory and filters records without changing their labels.

The report distinguishes received documents, documents with trainable spans, client-declared human documents, and simulated documents. Its `cord_test` result covers the canonical CORD test partition, and `by_source` separates gold from real OCR for each source. It also records test-membership, label, OCR, and canonical-model hashes. Test documents, test-derived documents, and renamed copies of frozen test OCR cannot enter training. A candidate is saved separately under `artifacts/retrained/`; this command neither promotes it nor changes the published Pages benchmark. No improvement is assumed: unchanged or worse before/after results are retained.
