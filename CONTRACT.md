# Integration contract

Demonstration documents only. Generated invoices contain fictional vendors and transactions. Public CORD receipts are attributed separately. Local review practice is stored only in this browser; server uploads require a configured API.

Python data uses plain JSON dictionaries. Token: text, box [x,y,width,height] normalized 0..1, confidence 0..1, label (optional). Document: id, type (invoice/purchase_order/receipt/other), vendor, number, date, due_date, currency, subtotal, tax, total, po_number, line_items [{description,quantity,unit_price,amount}], tokens, image (relative URL), source, split, defects. Extraction: fields mapping names to {value, confidence, box, trace [{step,detail}]}, line_items, backend, ocr_engine. Rules: [{id,name,status (pass/fail/not_applicable),message}]. Queue item combines document and extraction plus rules, status (needs_review/auto_approved/accepted/rejected), risk, created_at.

Pipeline module packages.pipeline exposes process_document(document, backend='rules') returning a queue item and process_image(image_bytes, filename) returning a redacted queue item with redacted bytes returned separately if needed; agents coordinate exact signature. The seed bundle is web/public/data/demo.json with {documents: [], evaluation: manifest}. Results live in results/manifest.json. Every measurement states population, split, n, method; unavailable observations use null and a reason, never invented metrics.

API GET /health, GET /v1/queue, GET /v1/documents/{id}, GET /v1/trace/{id}, POST /v1/review/{id} {fields:{name:value},line_items:[],decision:accept/reject,reason}, POST /v1/documents multipart, POST /v1/extract, POST /v1/retrain. Token-gated writes via Authorization: Bearer. Seed API from demo bundle, SQLAlchemy supports SQLite and Postgres. Frontend static export Next.js with /docket basePath, reviewer /review?id=... for arbitrary uploaded ids. Root owns workflow, docs, deployment. Each agent owns its module tests and commits its files only.
